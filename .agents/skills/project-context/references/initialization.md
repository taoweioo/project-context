# 前端项目初始化分析规则

用户明确要求初始化前端项目持久化上下文时，按本流程分析项目并生成初始上下文单元。

## 前置检查

在读取业务代码或创建任何文件前，必须完成以下检查：

1. 确认当前工作区存在可识别的前端项目。可依据前端框架依赖、构建配置、页面或组件源码目录，以及前端开发脚本判断。
2. 如果无法确认存在前端项目，停止初始化，不创建任何上下文单元，并说明缺少的证据。
3. 如果工作区包含多个可识别的前端应用，例如 monorepo 中的多个 `apps/*` 或 `packages/*`，列出候选应用路径并等待用户指定目标；不能跨应用混合提取规则。
4. 检查目标项目的 `.agents/skills/`。本机制只创建和维护名称以 `ctx-` 开头的目录；其他 skill 目录可以读取，但不创建、修改、移动或删除。
5. 如果目标 `ctx-*` 路径已存在，说明该项目已初始化过对应主题；本次初始化不覆盖该文件，记录冲突并等待用户决定。

## 敏感信息保护

初始化过程中不得将敏感信息写入任何 `ctx-*` 上下文单元、初始化报告或对话输出。

- 不读取或复制 `.env`、`.env.*`、凭据文件、私钥、Cookie、访问令牌和连接字符串中的实际值。
- 环境变量只能从 `.env.example`、配置 schema、源码中的变量引用或用户明确提供的非敏感说明中提取名称和用途。
- 可以记录环境变量的名称、用途和配置入口；不得记录其实际值。
- 如果无法确认某项配置是否包含敏感信息，默认不提取，并列入待确认项。

## 项目基础上下文

前置检查通过后，必须创建：

```text
.agents/skills/ctx-project-baseline/SKILL.md
```

项目基础上下文只记录能够从项目配置、目录结构和项目指令文件中确认的工程事实：

- 前端框架、主要语言和包管理工具。
- 已确认的开发、测试、Lint 和构建命令。
- 前端源码根目录。
- 页面或路由入口。
- 主要配置文件和环境变量入口。
- 接口层、状态层和样式层的入口位置。
- 项目指令文件及其适用范围。

项目基础上下文不得记录：

- 业务规则、权限规则或单个页面流程。
- 未证实的工程偏好。
- 大段目录清单或大段源码。
- 从单个组件或单个文件推导出的通用规范。

## 分析范围

默认不递归读取以下目录或文件：

- `node_modules/`、`.git/` 和依赖包源码。
- `dist/`、`build/`、`coverage/`、`.next/`、`.nuxt/`、`.turbo/`、`.cache/` 和其他构建产物、测试产物或缓存。
- 临时目录、压缩文件、二进制文件和自动生成文件。
- 锁文件的完整内容；锁文件只用于确认包管理工具和必要的依赖信息。
- `.env`、`.env.*`、凭据文件和其他可能包含敏感信息的文件。

README、`AGENTS.md`、项目说明和必要配置文件不属于默认排除范围，但只按当前初始化目标读取。

先读取项目基础资料：

- `AGENTS.md`、README 和其他项目指令文件。
- `package.json`、锁文件名称和包管理工具配置。锁文件只用于确认包管理工具和必要的依赖信息，不默认逐行读取。
- 构建、环境变量、Lint、格式化、测试和样式配置。
- 根目录和前端源码目录的结构。

然后按需检查高价值区域：

- 路由和页面入口。
- 数据请求、接口封装、缓存和全局状态。
- URL 参数、浏览器存储、事件和共享数据契约。
- 权限、前端业务限制和错误降级。
- 文件上传、下载、导出等跨页面能力。
- 第三方前端服务、SDK 或组件库集成。
- 高频复用且包含复杂逻辑的共享代码。

不要为了“全面扫描”而读取每个文件。优先读取入口、配置、中心封装和具有高引用价值的代码。

## 生成步骤

1. 完成前置检查。
2. 读取 `selection.md`、`taxonomy.md` 和 `template.md`。
3. 创建项目基础上下文。
4. 从高价值区域识别候选知识边界。
5. 使用 `selection.md` 判断每个候选知识应独立提取、写入项目基础上下文、列入待确认项或跳过。
6. 对需要独立提取的候选知识，使用 `taxonomy.md` 确定职责边界、目标路径和名称。
7. 按 `template.md` 和 `taxonomy.md` 的 `ctx-` 命名规则创建专项上下文单元。
8. 输出初始化报告。

是否创建专项上下文单元，必须完全遵循 `selection.md`。本文件不另行定义生成门槛。

## 证据强度

- 项目指令文件、配置和用户确认的业务说明：可写为明确规则。
- 多处代码一致体现的模式：写为“当前项目约定”或“当前代码中”。
- 单个文件或单个分支中的实现：写为“基于当前代码”，并列入待确认项。
- 代码与项目说明冲突：不创建结论，列入待确认项。

## 初始化报告

```text
初始化结果：
- 项目基础上下文：路径与摘要
- 独立上下文单元：路径、职责与证据
- 写入项目基础上下文的事实：摘要
- 跳过：候选主题与原因
- 待确认：无法仅凭现有证据判断的问题
```

## 完成前检查

输出结果前确认：

- 已确认目标是单个前端项目。
- 项目基础上下文只包含工程事实。
- 每个专项上下文单元均通过 `selection.md` 的全部判断条件。
- 每个已创建文件都符合 `taxonomy.md` 的 `ctx-` 路径和命名规则。
- 没有修改、移动或删除其他 `.agents/skills/` 目录。
- 没有覆盖已有的 `ctx-*` 上下文单元。
