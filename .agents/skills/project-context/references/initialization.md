# 初始化规则

用户明确要求初始化前端项目持久化上下文时，建立最小、可验证的 `ctx-*` skill 集合及必要的内部资源。

## 前置检查

1. 阅读项目指令、包管理和构建配置、源码根目录及测试入口；不读取敏感配置值。
2. 检查当前工作树和现有 `.agents/skills/ctx-*/`；保留用户已有改动，不覆盖非 `ctx-*` skill。
3. 读取 `selection.md`、`taxonomy.md`、`template.md`、`references.md`。
4. 只按需读取能验证候选知识的代码、配置、测试和用户说明；不为追求全面扫描全部代码。

## 生成流程

1. 创建固定的 `ctx-project-baseline/SKILL.md`，仅记录有证据的工程基础事实。
2. 识别跨文件契约、运行时边界、跨模块规则、复用能力和高风险防护等候选知识。
3. 按 `selection.md` 逐项决定创建、写入项目基础上下文、待确认或跳过。
4. 新建 skill 时按 `taxonomy.md` 和 `template.md` 写入最小 `SKILL.md`。
5. 只有复杂知识通过 `references.md` 的准入判断时，才创建其内部 `references/` 文件，并在 `SKILL.md` 写明读取条件。

## 只分析模式

用户要求只规划时，不创建或修改文件。输出预计创建的 skill、其职责和证据、预计的内部 resource、待确认与跳过项。

## 报告与检查

报告分别列出：已创建、已更新、内部 reference、写入项目基础上下文、待确认、跳过和已检查无需创建。

完成前确认：每个 skill 有独立加载原因和证据；不存在重复主题；reference 有读取条件且未替代关键结论；未写入敏感信息；未修改 `docs/` 或非 `ctx-*` skill。实际写入时输出 `project-context：已更新`。
