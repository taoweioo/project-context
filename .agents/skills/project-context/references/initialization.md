# 初始化规则

用户明确要求初始化前端项目持久化上下文时，本文件负责项目检查和初始候选内容生成。它不直接创建或修改 `ctx-*`。

## 前置检查

1. 阅读项目指令、包管理和构建配置、源码根目录及测试入口；不读取敏感配置值。
2. 检查当前工作树、现有分类级 `ctx-*` 和旧版 `ctx-<分类>-<主题>`；`ctx-project-baseline` 始终按规范入口处理，不计入旧结构。保留用户已有改动，不覆盖非 `ctx-*` skill。
3. 只按需读取能验证候选内容的代码、配置、测试和用户说明；不为追求全面扫描全部代码。

## 生成候选内容

1. 生成项目基础候选内容，包括有证据的技术栈、包管理、构建、源码入口、测试和全局工程约定。
2. 识别架构候选内容时，区分可从代码和配置证明的当前架构，以及由用户说明、项目指令或已确认方案证明的目标架构、演进路径和决策约束；记录相关项目基础候选内容作为上游依据，不把计划状态写成当前事实。
3. 识别跨文件契约、运行时边界、跨模块规则、复用能力、高风险防护和具有长期价值的模块流程等其他候选内容。
4. 按可独立证实的知识边界拆分候选，为每项记录结论、证据来源和可能相关的既有上下文；证据不足的内容仍标为待核对候选，不写成事实。
5. 不按页面、功能或代码目录生成顶层 skill 候选，也不预先创建全部分类。具体分类、分类级 skill 和内部 reference 由维护流程决定。
6. 项目基础候选内容的目标固定为 `ctx-project-baseline`；目标不存在时标明需要首次创建。

## 交给维护流程

将初始候选内容、初始化来源和用户是否要求只分析或规划一并交给 [维护流程](./maintenance.md)。由维护流程调用选择规则、执行选择结果并输出初始化结果。

本文件不单独输出维护结果，也不直接读取 `taxonomy.md`、`template.md` 或 `internal-references.md`。
