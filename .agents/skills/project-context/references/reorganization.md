# ctx skill 结构调整规则

当用户明确要求删除、拆分、合并、重命名、移动或整理已有 `ctx-*` skill，或其内部文件与目录（包括 `references/`）时，按本规则处理。结构调整不是自动行为；固定的 `ctx-project-baseline` 只能进行内容维护。

## 范围

只调整直接位于 `.agents/skills/` 下的 `ctx-*` 目录及其内部文件。不调整 `project-context` 管理 skill、非 `ctx-*` skill、项目代码、配置、Git 历史或 `docs/`。

## 计划与确认

先读取全部受影响 skill、其内部资源、其他 skill 对其 `SKILL.md` 的具体链接，以及必要证据。输出计划，至少列出：

- 目标与原因；
- 受影响的 skill、内部 resource 与链接；
- 每项规则和证据的去向；
- 删除、迁移或保留策略；
- 风险和完成检查。

未获得用户明确确认前，不得修改任何受影响文件。确认后重新读取目标与链接，再执行已确认计划。

## 执行约束

- 拆分时，每个新 skill 必须有独立加载原因；内部 reference 随其职责迁移或拆分，不跨职责复制。
- 合并时，保留一个清晰职责边界；删除重复内容、更新相关 skill 链接，并重新判断 reference 是否仍有准入价值。
- 重命名或移动时，更新所有失效的相对链接和 `SKILL.md` 中的按需读取路径。
- 删除 skill 或内部 resource 时，先确认没有仍需保留的规则；删除 reference 前，移除或修正入口中的读取链接。
- 不因结构调整自动改写用户明确规则；其迁移、保留或删除必须在计划中说明。

执行后报告实际变更、更新的链接、保留/迁移/删除的规则和验证结果。
