# ctx skill 审计规则

当用户明确要求审计、检查或评估前端项目的持久化上下文时，执行只读检查。范围仅包括直接位于 `.agents/skills/` 下的 `ctx-*` skill 及其内部资源；不检查或维护 `docs/`、非 `ctx-*` skill、业务代码（除非用于核实证据）和敏感配置值。

## 审计步骤

1. 检查工作树；存在未提交变更时，将其作为当前实现的一部分，不覆盖或还原。
2. 读取每个有效目标的完整 `SKILL.md`，以及被它明确引用的内部 resource。
3. 依据 [选择规则](./selection.md) 检查内容是否仍应保留，以及归属是否正确。
4. 依据 [分类规则](./taxonomy.md)、[结构规则](./template.md) 和 [内部 reference 规则](./internal-references.md) 检查名称、职责、触发、内容分工和内部链接。
5. 仅按需读取代码、配置、项目指令或用户说明来核对具体结论。
6. 无法证实的问题列入待确认，不推断为错误；整个审计不得修改文件。

## 检查项

### skill 入口

- 目录是否含有可读取的 `SKILL.md`，frontmatter 的 `name`、`description` 是否非空且与目录一致。
- `description` 是否说明正确触发范围及相近的不适用范围，避免过宽或过窄。
- “负责范围”是否只承担一个加载原因；相邻 skill 是否重复或明显重叠。
- 关键入口、事实、约束和用户明确规则是否有可定位证据，且当前路径仍存在。
- 是否把当前局部实现、临时调试或未确认猜测写成长期事实。

### 内部 resources

- `SKILL.md` 中引用的相对路径是否真实存在且仍属于当前 skill。
- 每个 reference 是否有精确读取条件；没有条件的文件应报告为压缩或删除候选。
- reference 是否仍通过 `internal-references.md` 的准入判断，是否与 skill 职责一致，是否错误成为跨 skill 共享库。
- reference 是否重复 `SKILL.md` 的独立事实、复制普通源码或缺少关键证据。
- 当前实现变化使 reference 或读取条件不一致时，报告“当前工作树不一致”；仅能证明稳定移除时才报告为过期规则。

## 报告

按 High、Medium、Low、未发现问题、待确认、工作树说明输出。High 表示可能误导后续修改、泄露敏感信息或使关键 skill/resource 无法正确加载；Medium 表示职责、证据、路径或准入问题；Low 表示不直接误导的命名、表达或链接说明问题。

用户指定不存在的路径、非 `ctx-*` skill 或 `docs/` 路径时，列入“未纳入审计”。未发现任何可审计的 `ctx-*` skill 时，报告“未发现可审计的 ctx-* 上下文单元”，不得写成“未发现问题”。

用户明确要求修复审计问题时，将问题和证据作为新的候选内容交给 [维护流程](./maintenance.md)。审计本身不自动修改文件或触发维护。
