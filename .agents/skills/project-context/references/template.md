# ctx skill 结构

每个 `ctx-*` 都是一个完整 skill，`SKILL.md` 是其必需入口。

## 组成部分与分工

各类信息应按其使用时机放入对应位置。

| 内容 | 位置 | 适用条件 |
| --- | --- | --- |
| skill 的触发条件 | `SKILL.md` 的 frontmatter（`description`） | 用于定义 skill 的触发边界，只写适用任务和必要的非适用范围。 |
| 每次使用都需要的职责、关键约束和入口 | `SKILL.md` 正文 | 加载 skill 后立即影响执行，并且能够用简短、独立条目表达。 |
| 特定子任务需要的复杂资料 | `references/` | 仅在特定条件下读取，且需要连续理解流程、关系、规则或示例。 |
| 可重复且需要确定结果的操作 | `scripts/` | 重复执行或确定性操作能够用脚本提高可靠性。 |
| 用于生成交付物的材料 | `assets/` | 会被复制、嵌入或改造成输出，不作为 agent 指令加载。 |

## SKILL.md 最小模板

`SKILL.md` 至少包含 frontmatter、一级标题、`负责范围`、`关键入口与对象`、`已确认事实与约束` 和 `证据来源`。

```md
---
name: ctx-architecture-data-fetching-and-cache
description: 当修改跨页面数据请求、缓存键、失效策略或加载边界时使用；不适用于单个页面的局部请求状态或模块专属接口字段。
---

# 前端架构：数据请求与缓存

## 负责范围

说明唯一职责和加载原因。

## 关键入口与对象

只列修改时必须关注的高价值文件、字段、参数或事件。

## 已确认事实与约束

写明已确认、长期有效且会改变修改决策的事实或约束。

## 证据来源

- 缓存键组织规则：代码 `src/services/query-client.ts`
- 数据失效策略：项目约定 `AGENTS.md`
```

只有内容确有必要时，才增加 `不负责范围`、`核心流程`、`防护约束`、`用户明确规则`、`按需读取`、`相关上下文单元` 和 `待确认事项`；不保留空标题。

当复杂内容不适合写入 `SKILL.md` 时，使用 `按需读取` 指向当前 skill 的 `references/` 中承载该内容的文件，并说明何时读取：

```md
## 按需读取

- 修改缓存键、失效顺序或跨页面同步前，读取 [缓存一致性](./references/cache-consistency.md)。
```
