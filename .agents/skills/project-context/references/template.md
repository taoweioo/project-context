# 上下文单元模板

每个上下文单元由一个独立的 `SKILL.md` 表示。它只负责一个明确的知识边界；不适用的按需章节不要保留空标题。用户明确要求项目文档并建立关联后，上下文单元按 `documentation.md` 增加主文档导航。

## 模板结构

每个上下文单元必须包含：

- frontmatter 中非空的 `name` 和 `description`。
- 使用“中文分类名：中文主题”的一级标题。
- `负责范围`。
- `关键入口与对象`。
- `已确认事实与约束`。
- `证据来源`。

以下章节只在确实需要时出现：

- `不负责范围`。
- `核心流程`。
- `防护约束`。
- `相关上下文单元`。
- `待确认事项`。

已经关联主文档的上下文单元还必须包含 `关联项目文档`。没有主文档的上下文单元不得保留空的关联章节。

```md
---
name: ctx-architecture-data-fetching-and-cache
description: 当修改跨页面数据请求、缓存键、失效策略或加载边界时使用；不适用于单个页面的局部请求状态或模块专属接口字段。
---

# 前端架构：数据请求与缓存

## 负责范围

说明这份上下文单元负责的明确边界，以及它为什么需要在相关前端任务中加载。

## 关键入口与对象

只列高价值文件、字段、参数、事件或数据契约，并说明它们的重要性。

## 已确认事实与约束

记录后续 AI 必须遵守的已确认工程事实、联动修改要求、数据语义、流程约定或产品限制。

已经关联主文档时，只保留任务开始前无法延迟加载的最小摘要和防护约束。完整流程、规则关系、示例和设计原因写入关联项目文档。

## 证据来源

每条证据都要说明它支撑哪项事实或约束：

- 缓存键组织规则：代码 `src/services/query-client.ts`
- 数据失效策略：项目约定 `AGENTS.md`
- 某项产品限制：用户明确规则

## 不负责范围

只在容易和相邻上下文单元混淆时，说明不属于本文件的主题及其归属。

## 核心流程

只有当流程复杂且不容易从代码直接看出时，说明路由、状态、接口、缓存、事件、URL 参数或浏览器存储的流转关系。

## 防护约束

记录高风险限制、历史问题和禁止事项，并说明原因。

## 相关上下文单元

列出职责边界之外、但修改当前区域时必须一起检查的上下文单元；使用仓库内相对路径指向具体的 `SKILL.md`，并说明关联原因。

## 关联项目文档

只用于已经关联主文档的上下文单元。使用仓库内相对路径指向对应章节，并明确文档职责和加载要求：

- 主文档：[缓存一致性](../../../docs/project-context/cache-consistency.md#缓存失效)
- 文档职责：说明跨模块缓存一致性的完整流程。
- 加载要求：修改跨页面缓存键、失效顺序或降级流程前，必须先读取该文档。

## 待确认事项

只记录已明确归属、但暂时不能写成稳定事实的事项。每项必须包含：

- 尚未确认的问题。
- 当前已有的证据。
- 还需要什么信息才能确认。
```

## 命名说明

将示例中的 `architecture` 替换为分类规则中对应中文分类所使用的固定英文标识，将 `data-fetching-and-cache` 替换为实际知识主题。目录名和 frontmatter 的 `name` 必须完全一致；一级标题使用“中文分类名：中文主题”，不必与 `name` 相同。

## 写作规则

- 一级标题使用“中文分类名：中文主题”，例如“前端架构：数据请求与缓存”；目录名和 frontmatter 的 `name` 仍使用固定英文标识。
- `description` 是主要触发机制，必须同时说明适用任务或对象，以及相似但不应触发的范围。
- `负责范围` 只说明一个知识边界；不通过堆砌关键词扩大触发范围。
- `关键入口与对象` 只保留后续修改时必须关注的高价值入口，不复制目录树或普通实现细节。
- `已确认事实与约束` 只记录已确认的长期知识；局部实现推导出的结论要标注“当前代码中”或“基于当前代码”。
- 已经关联主文档时，`已确认事实与约束` 只保留最小摘要和防护约束，不复制关联文档的完整流程、决策表、示例或设计原因。
- `证据来源` 必须将每项重要事实或约束与代码、项目约定、配置或用户明确规则对应起来；不只罗列无对应关系的文件清单。
- `待确认事项` 不能改变 `description`、`负责范围` 或已确认事实；不能据此创建新的上下文单元。
- 不复制大段源码，不写通用教程、代码模板、临时调试信息或未经确认的猜测。
- 相关上下文单元使用仓库内相对路径，指向具体的 `SKILL.md`。
- 已经关联主文档的上下文单元必须按 `documentation.md` 建立双向关联；`关联项目文档` 必须说明文档职责、对应章节和加载要求。
- 初始化或手动维护创建的上下文单元目录和 frontmatter 的 `name` 必须以 `ctx-` 开头。
- 如果当前规则属于其他上下文单元，不要重复记录，改为链接对应文件。
- 不添加作者、版本号、最后更新时间、变更日志、完整目录树或测试记录；Git 负责文件历史，上下文单元只保留当前仍有效的知识。
