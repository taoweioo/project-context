# ctx skill 模板

每个 `ctx-*` 是一个完整 skill，必须包含独立的 `SKILL.md`。`references/`、`scripts/`、`assets/` 等均为按需存在的内部资源，不构成固定的完整结构。

## SKILL.md 必需结构

```md
---
name: ctx-architecture-data-fetching-and-cache
description: 当修改跨页面数据请求、缓存键、失效策略或加载边界时使用；不适用于单个页面的局部请求状态或模块专属接口字段。
---

# 前端架构：数据请求与缓存

## 负责范围

说明唯一的职责边界和加载原因。

## 关键入口与对象

只列修改时必须关注的高价值文件、字段、参数或事件。

## 已确认事实与约束

写明已确认、长期有效且会改变修改决策的事实或约束。

## 证据来源

- 缓存键组织规则：代码 `src/services/query-client.ts`
- 数据失效策略：项目约定 `AGENTS.md`
```

按需要加入：`不负责范围`、`核心流程`、`防护约束`、`用户明确规则`、`按需读取`、`相关上下文单元`、`待确认事项`。不保留空标题。

## 内部 references

当 `references.md` 的准入条件成立时，在 `SKILL.md` 增加“按需读取”章节：

```md
## 按需读取

- 修改任务状态流转、轮询或失败处理前，读取 [导出任务状态](./references/export-job-state.md)。
```

- 每一项都使用相对于所属 `SKILL.md` 的路径，并给出精确读取条件。
- `SKILL.md` 保留修改时必须立即知道的结论；不得把关键约束完全藏进 reference。
- reference 只承载同一职责边界内、需要连续理解的补充知识；详细规则见 `references.md`。

## 写作规则

- `description` 同时写明适用任务与不适用的相近范围。
- 不复制大段源码、目录树、通用教程或临时调试信息。
- 每条重要事实或约束都对应可定位的证据。
- 用户明确要求长期保留的外部规则放入“用户明确规则”，并保留规则内容、来源、记录日期和“有效”状态；除非用户明确修正，不因代码观察自动改写。
- 相关 skill 使用仓库内相对路径指向具体 `SKILL.md`；不要直接链接其他 skill 私有的 reference。
