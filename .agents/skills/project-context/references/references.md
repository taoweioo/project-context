# ctx skill 内部参考资料规则

本文件规定 `ctx-*` skill 何时创建和维护其内部 `references/` 资源。它不定义通用 skill 的完整目录结构：`SKILL.md` 是 skill 的必需入口，`references/` 只是可选的内部资源目录之一；skill 也可以按需拥有 `scripts/`、`assets/`、模板或其他资源。

## 定位

`SKILL.md` 承载任务触发、职责边界、关键入口、简短且可独立理解的事实与约束，以及按需读取内部资源的条件。

`references/` 承载同一职责边界内、无法安全压缩进 `SKILL.md` 的项目知识。它是所属 `ctx-*` skill 的内部资源，不是项目级文档目录，也不由本机制管理 `docs/`。

## 准入判断

新增或扩展 reference 前，先尝试将知识压缩为：职责说明、一组高价值入口、若干独立事实与约束，以及必要的证据。

只有同时满足以下条件，才创建或更新 `references/` 中的文件：

1. 只读取 `SKILL.md` 会丢失完成相关修改所必需的判断；
2. 这些信息仍属于同一个 `ctx-*` 的职责边界；
3. 内容需要连续理解一组关系，不能安全拆成 `SKILL.md` 中的独立事实；
4. 有可定位的代码、配置、项目指令或用户明确说明作为证据；
5. 能为该文件写出具体的按需读取条件。

适合写入 reference 的内容包括：

- 多阶段流程、状态转换、时序与会改变结果的异常分支；
- 需要决策表表达的条件组合、优先级、互斥或覆盖关系；
- 必须联合理解的跨文件或跨模块关系；
- 历史事故的完整因果与防护理由，简写会导致再次误用；
- 彼此关联、无法拆分为独立条目的字段、事件或状态语义；
- 用户明确要求长期保留的完整业务背景。

以下内容不得仅因篇幅较长而写入 reference：单个文件可直接理解的实现、普通入口清单、通用教程、源码摘录、临时排查过程、未经确认的推测，以及可安全压缩为独立约束的知识。

## 文件与内容

reference 位于所属 skill 目录：

```text
.agents/skills/ctx-<分类>-<主题>/
├── SKILL.md
└── references/
    └── <主题>.md
```

- 文件名使用小写英文和连字符，表达需要独立读取的知识主题；不使用 `ctx-`、`new`、`update`、`issue` 等临时词。
- 一个 reference 只服务一个明确的连续理解主题；不按页面目录或单个代码文件机械拆分。
- `SKILL.md` 必须用仓库内相对路径链接每个 reference，并说明精确读取条件；没有读取条件的 reference 应压缩回 `SKILL.md` 或移除。
- reference 默认私有于所属 skill。另一个 `ctx-*` 不直接依赖它；若同一知识确实被多个 skill 修改时都必须加载，应重新判断是否需要一个职责正确的独立 `ctx-*`。
- reference 不要求固定模板。按内容需要使用“何时读取”“流程 / 决策”“关键约束”“证据来源”“待确认事项”等章节，不保留空标题。
- 重要结论仍需指向证据；用户明确规则须保留来源、记录日期和状态。

## 维护与审计

- 新建或明显扩展 reference 时，先按本文件完成准入判断，再按 `template.md` 更新 `SKILL.md` 中的按需读取说明。
- 更新 `SKILL.md` 的事实或约束时，检查其引用的 reference 是否仍一致；只修改受影响内容，不制造无意义的同步变更。
- 移动、重命名、拆分、合并或删除 `references/` 中的文件属于所属 `ctx-*` 的结构调整，按 `reorganization.md` 先规划并等待用户确认。
- 审计时检查 reference 路径、读取条件、职责归属、关键事实与证据；不检查或维护 `docs/`。
