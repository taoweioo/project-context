# ctx skill 内部 references 规则

`references/` 是可选的 skill 内部资料目录。它只承载同一职责边界内、不能安全压缩进 `SKILL.md` 的信息；不定义完整 skill 结构，也不是项目级文档库。

## 准入判断

新增或明显扩展 reference 前，先尝试把知识压缩为 `SKILL.md` 中的职责说明、高价值入口、独立事实与约束，以及必要证据。

只有同时满足以下条件，才创建或更新 reference：

1. 不读取该资料会丢失完成特定子任务所必需的判断；
2. 它仍属于一个 `ctx-*` 的职责边界；
3. 内容需要连续理解一组关系，不能安全拆成独立条目；
4. 有可定位的代码、配置、项目指令或用户明确说明作为证据；
5. `SKILL.md` 能写出具体的读取条件。

典型内容包括多阶段流程、状态转换、时序、条件组合与优先级、联合理解的跨文件关系、完整事故因果，以及无法拆分的字段或状态语义。

单个文件可直接理解的实现、普通入口清单、通用教程、源码摘录、临时排查过程、未经确认的推测，以及可安全压缩为独立约束的知识不写入 reference。

## 组织与路由

```text
.agents/skills/ctx-<分类>-<主题>/
├── SKILL.md
└── references/
    └── <读取主题>.md
```

- 文件名使用小写英文和连字符，表达具体读取主题；不使用 `ctx-`、`new`、`update`、`issue` 等临时词。
- 按读取原因拆分，而非按资料类型或代码目录拆分。例如使用 `export-job-state.md`，不使用泛泛的 `workflow.md`、`notes.md` 或 `evidence.md`。
- 每个文件在 `SKILL.md` 中有相对路径和精确读取条件；无读取条件的内容应压缩回正文或移除。
- reference 默认私有于所属 skill。另一个 `ctx-*` 不直接依赖它；同一知识确实被多个 skill 修改时都必须加载，应重新判断是否需要职责正确的独立 skill。
- 不要求固定章节。按内容需要使用“何时读取”“流程 / 决策”“关键约束”“证据来源”和“待确认事项”等章节，不保留空标题。

## 维护与审计

- 更新 `SKILL.md` 的事实或约束时，检查引用的 reference 是否仍一致；只修改受影响内容。
- 需要重复执行且必须确定结果的操作，应评估 `scripts/`，不要把可执行流程伪装成 reference。
- 会成为交付物的模板、图片或代码骨架，应评估 `assets/`，不要作为 instructions 加载。
- 移动、重命名、拆分、合并或删除 reference 属于所属 skill 的结构调整，按 `reorganization.md` 先规划并等待确认。
- 审计时检查路径、读取条件、职责归属、准入判断、结论与证据；不检查或维护 `docs/`。
