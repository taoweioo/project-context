# 上下文单元选择规则

仅当没有职责匹配的既有 `ctx-*` skill 时，才用本规则判断是否新建上下文单元。用户明确要求单独建立 skill 时可绕过“值得提取”门槛，但仍须遵守敏感信息、命名、冲突和重复检查。

## 必须同时满足的条件

候选知识必须：

1. 属于前端项目；
2. 在后续任务中会改变判断、修改路径或错误风险；
3. 不易从单个文件直接得出；
4. 有代码、配置、项目指令或用户明确说明作为证据；
5. 有稳定且独立的加载原因；
6. 不属于既有 `ctx-*` 的职责边界，也不是普通项目基础事实；
7. 不是临时调试、单次实现、通用知识或未经确认的猜测。

任一条件不满足时，不新建 skill。属于全项目工程事实但不足以独立加载的内容，写入 `ctx-project-baseline`；无法确认的内容列入待确认。

## 职责边界

先按 `taxonomy.md` 分类，再用一句话说明“修改什么时必须加载它”。如果该句无法与相邻 skill 区分，说明边界尚不清楚，不创建。

一个 skill 只承载一个加载原因。相互独立、可以在未来单独修改的知识不能因出现在同一任务中而合并。反之，同一职责内无法安全压缩的连续关系，应按 `references.md` 放入该 skill 的内部 `references/`，而不是新建重复 skill。

## 创建前检查

- 检查 `.agents/skills/ctx-*/SKILL.md`，排除重复或重叠归属。
- 按 `taxonomy.md` 确定目录、分类和名称。
- 按 `template.md` 创建最小 `SKILL.md`。
- 按 `references.md` 判断是否还需要内部参考资料。
- 不创建空目录、空 reference 或只含文件清单的 skill。
