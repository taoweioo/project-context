# 前端项目持久化上下文初始化

## 目标

为当前前端项目建立最小、准确且可按需加载的初始持久化上下文集合。上下文单元只记录具有长期价值、且不容易从单个文件直接看出的项目知识。

## 适用边界

只有用户明确要求初始化前端项目持久化上下文时，才执行本 skill。

本 skill 当前不处理：

- 普通功能开发或代码修改。
- 代码修改后的自动检查、自动提示或自动更新。
- 已有上下文单元的更新、审计、拆分、合并或重组。
- 后端项目的规则提炼。

## 初始化前必须读取的规则

每次初始化都必须读取：

- `references/selection.md`：判断候选知识是否值得提取。
- `references/taxonomy.md`：确定已选知识的职责边界、目标目录和命名。
- `references/template.md`：按统一模板生成上下文单元。
- `references/initialization.md`：执行前端项目的前置检查、分析和生成流程。

## 初始化原则

- 用户的初始化请求只授权创建新的初始上下文单元，不授权覆盖已有人工维护的内容。
- 只有前置检查确认目标是单个可识别的前端项目后，才创建项目基础上下文。
- 是否创建专项上下文单元，必须完全遵循 `references/selection.md`；其他文件不得重复定义生成门槛。
- 不因目录存在、模式只出现一次，或代码看起来像最佳实践就生成上下文单元。
- 不创建空文件、通用开发教程、大段源码摘录或重复的权威说明。
- 所有重要结论都要在生成的上下文单元中注明证据来源。

## 初始化报告

完成后使用以下格式：

```text
初始化结果：
- 项目基础上下文：路径与摘要
- 独立上下文单元：路径、职责与证据
- 写入项目基础上下文的事实：摘要
- 跳过：候选主题与原因
- 待确认：无法仅凭现有证据判断的问题
```
